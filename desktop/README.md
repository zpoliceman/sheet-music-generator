# 弦页制谱 v1.0.3 使用说明

发布日期：2026-10-22。适用于64位Windows桌面程序。

弦页制谱在你的电脑上分析歌曲和TXT歌词，生成可试听、可编辑右手型的人声简谱与吉他伴奏六线谱，再导出PDF或整套JPG。程序输出的是**待校对自动草稿**，你仍需试听并检查音高、节奏、歌词和伴奏；本版不提供完整吉他指弹独奏或钢琴双手谱的桌面生成入口。

## 1. 下载哪些文件

打开 [v1.0.3 发布页](https://github.com/zpoliceman/sheet-music-generator/releases/tag/v1.0.3)，展开 Assets（附件）。

| 文件 | 用途 |
| --- | --- |
| `sheet-music-generator-v1.0.3-win64.zip` | 建议下载。包含已编译EXE、同版项目源码和说明；解压到你有写入权限的文件夹。 |
| `弦页制谱.exe` | 单独的桌面入口。已经准备好v1.0.3项目及环境时使用，放到项目根目录。 |
| `使用说明-v1.0.3.md` | 本说明的独立副本，可在GitHub或文本编辑器中阅读。 |
| `SHA256SUMS.txt` | 上述三个附件的SHA-256摘要，用于核对下载文件是否完整。 |
| GitHub提供的`Source code` | 纯源码存档，没有已编译EXE；需要另下载EXE或自行编译。 |

不要在压缩包内部直接运行EXE。完整解压后，EXE应与`README.md`、`desktop/`、`tools/`、`HTML/`处于同一层目录。**压缩包未包含Python运行环境、模型权重或外部工具，解压本身并不代表已经能制谱。** 不要只复制EXE到桌面；需要快捷入口时，为原位置的EXE创建快捷方式。

如果你要升级旧项目，先备份原项目并关闭正在生成的桌面程序。把v1.0.3源码和EXE更新到原项目位置，保留原来的`.venv-gpu/`、`HTML/.venv/`、`.tools/`、`.cache/`、`third_party/`、`data/`、`test_music/`和`test_outputs/`等本机目录。新压缩包不含这些目录，不要先删除它们，也不要只换EXE而保留旧源码。依赖有缺项时，按下节补装。

## 2. 首次准备环境

完整制谱需要64位Windows、Python 3.11、PowerShell、支持CUDA的NVIDIA显卡及匹配驱动。CUDA是NVIDIA显卡运行本项目模型所用的计算平台。桌面窗口依赖.NET Framework 4.8；PDF／JPG导出需要默认位置安装的Google Chrome和微软雅黑字体。只有CPU或其他品牌显卡的完整流程尚未验证，本版没有给出最低显存或处理时间保证。

以下操作均在**包含EXE的项目根目录**打开PowerShell后执行。先创建主Python环境，再安装依赖：

```powershell
py -3.11 -m venv .venv-gpu
.\.venv-gpu\Scripts\python.exe -m pip install torch==2.7.1 torchaudio==2.7.1 --index-url https://download.pytorch.org/whl/cu128
.\.venv-gpu\Scripts\python.exe -m pip install -r requirements.txt
.\.venv-gpu\Scripts\python.exe -B tools/initialize_workspace.py
```

第二条命令安装CUDA 12.8版PyTorch，显卡驱动需要支持该版本。最后一条命令创建空白复核配置，保留已有配置。如果某条命令报错，先处理该条错误，再继续后面的步骤。

接着准备外部工具和模型：

| 依赖 | 项目中的位置与要求 |
| --- | --- |
| FFmpeg音频工具 | 将`ffmpeg.exe`和`ffprobe.exe`放在`.tools/ffmpeg/任意版本/bin/`。桌面后台会查找该目录；使用命令行入口时还需把该目录加入当前终端的`PATH`。 |
| NCM解码工具 | 将`ncmdump.exe`放在`.tools/ncmdump/`。当前音频检查入口即使输入MP3也会检查它。 |
| [ROSVOT旋律识别项目](https://github.com/RickyL-2000/ROSVOT) | 代码放`third_party/ROSVOT/`。当前接入提交为`3c8332b`；按上游说明准备ROSVOT、RWBD、RMVPE权重及配置，使其位于`checkpoints/rosvot/`、`checkpoints/rwbd/`、`checkpoints/rmvpe/`。官方权重摘要见`config/rosvot_weights.json`。 |
| [TIFA歌词对齐项目](https://github.com/openvpi/TIFA) | 代码放`third_party/TIFA/`，当前接入提交为`614a277`。按上游说明准备TIFA-1.0-ST模型及配置，放入`.cache/tifa/model/TIFA-1.0-ST/`，其中应有`model.pt`。 |

Demucs人声分离、Whisper语音识别和节拍模型首次运行时还可能下载文件，因此首次使用需要联网并预留模型与中间音频的磁盘空间。模型和第三方工具的获取、许可及安装要求以各自项目说明为准。

最后安装网页编辑与打印所需的独立环境：

```powershell
powershell.exe -NoProfile -ExecutionPolicy Bypass -File .\HTML\准备环境.ps1
```

这个脚本会安装`HTML/.venv/`环境、准备网页分享工具并检查打印环境。即使只用桌面入口，导出仍依赖其中的打印环境。

上述步骤依据当前工程依赖整理，**尚未在全新电脑完成从零安装验证**。安装Python依赖成功不等于模型权重、外部代码和打印环境已经齐全；若程序提示缺少文件，应按它给出的具体路径补齐。

## 3. 生成一首歌曲

1. 双击项目根目录的`弦页制谱.exe`，窗口标题应包含`v1.0.3`。
2. 选择音源，支持MP3、NCM、FLAC、WAV和M4A。准备音质清楚的完整歌曲；当前流程以五分钟以内的歌曲为范围。
3. 选择对应的TXT歌词文件，使用UTF-8编码的纯歌词文本。LRC是带时间戳的歌词格式，不能当作音源；你可以将歌词正文另存为TXT后选择。
4. 选择曲谱保存文件夹和格式：`PDF + 整套 JPG`、`PDF`或`整套 JPG`。要生成后直接保存成品，勾选“生成后自动导出”。
5. 点击“一键生成曲谱”。程序先识别和完整检查音频，再依次分离人声、识别旋律、对齐歌词、生成简谱与吉他伴奏。窗口显示当前步骤和日志；同一项目中的生成任务应依次执行。
6. 生成成功后，程序打开本机手型编辑网页。勾选自动导出时，程序还会将两种曲谱保存到所选位置下的新建子文件夹，不覆盖原文件。

FLAC、WAV等已经可读的音源保持原采样率和声道，不重复进行有损转码；NCM先还原音频，M4A准备为同长WAV。原音源和歌词保持不变。

本版保留节拍或原曲覆盖不确定的提示，并在草稿页面及每页PDF／JPG标记“待校对”。弦位、持续按弦、相对品位不超过12品和最短十六分音符等演奏检查仍会执行。检查通过也不等于音乐已经由人逐音认可。

## 4. 修改右手型并导出

网页提供55种4/4拍右手候选，包括分解、合拨和扫弦。先选择需要调整的起止小节，再选择手型与音符时值，预览谱面并试听；没有选择修改的范围沿用原谱。

修改完成后，**先在网页点击“保存并生成整曲”**。随后回到桌面窗口，点击“刷新版本”，选中刚保存的版本，再点击“一键导出曲谱”。只预览或试听而没有保存的改动，不会成为桌面可导出的版本。每次导出另建子文件夹；你可以通过窗口的打开文件夹按钮查看结果。

## 5. 取消、继续与重新打开

生成期间点击“取消当前任务”可停止本次运行。后台未及时处理取消请求时，桌面程序会结束本次任务启动的后台程序。关闭桌面窗口也会取消当前运行任务，因此不要把关窗口当作后台继续生成。

如果任务在旋律识别和歌词对齐完成后停止，你可以在“最近任务”选中它，点击“打开所选任务”，再点击“继续未完成任务”。程序先核对原音源、歌词和已保存步骤，符合条件时复用已完成的分析，把新生成内容另存到任务的`attempts/`子目录。原文件发生变化、早期分析未完成或校验未通过时，需要重新生成。

已经有完整曲谱的任务可以直接打开网页和导出，无需重新运行模型；此时“继续未完成任务”不可用是正常情况。任务出现不能继续的错误、后台无响应或单步超过上限时，窗口会显示具体原因并保留已有文件，不会把失败结果当作成功曲谱。

## 6. 文件保存在什么地方

| 位置 | 内容 |
| --- | --- |
| 你在窗口选择的保存位置 | PDF、JPG及相关导出文件；每次导出一个新子文件夹。 |
| `test_outputs/accompaniment_runs/desktop/任务编号/` | 每首歌的完整任务，包括输入快照、模型结果、曲谱、手型版本和日志。 |
| 任务目录中的`reports/`，以及续跑的`attempts/`目录 | 生成和继续任务的步骤日志，排查错误时保留。 |
| `test_outputs/desktop/` | 窗口设置、操作请求和桌面日志。 |
| `HTML/runtime/` | 本机网页运行文件及打印临时内容。 |

要以后继续修改某首歌，应保留它的完整任务目录。只有PDF／JPG能看谱，但不能代替可编辑工程。下载包不含私人歌曲、歌词、历史曲谱、访问码或本机模型。

## 7. 常见问题

**只下载EXE，双击后提示缺少程序或环境。** EXE只是桌面入口。请下载同版本组合压缩包，完整解压，再按第2节安装环境和模型；不要把旧版源码与新版EXE混用。

**窗口提示缺少`.venv-gpu`、`HTML/.venv`或`model.pt`。** 主Python环境、打印环境或模型还未准备好。根据提示的路径找到第2节对应步骤补齐；反复点击生成不会补装这些文件。

**Windows提示未知发布者。** 此EXE未附数字签名。先确认它来自本仓库v1.0.3页面，并用下方命令核对下载文件；不要通过关闭系统防护来解决来源不明文件的问题。

**网页没有打开，或旧网页地址失效。** 本机手型网页由任务启动的服务提供，地址中的端口可能变化。回到桌面程序，从最近任务重新打开，并使用窗口提供的编辑入口。

**PDF／JPG导出失败。** 先查看窗口中显示的具体错误，确认`HTML/准备环境.ps1`执行成功、Chrome安装在默认位置、微软雅黑字体可用。如果错误涉及某个小节或打印版面，请保留任务和日志供排查，不能把缺页的结果当作整套曲谱。

**朋友上传歌曲后没有自动生成。** 统一朋友网页目前支持素材上传、已有曲谱查看、下载与编辑；新上传歌曲的整首模型生成尚未接入该网页，需要在本机桌面程序中发起。朋友网页的分享操作见仓库内`HTML/README.md`。

在下载目录打开PowerShell，可检查某个附件的SHA-256摘要，并与`SHA256SUMS.txt`同名行逐字核对：

```powershell
Get-FileHash -Algorithm SHA256 -LiteralPath .\sheet-music-generator-v1.0.3-win64.zip
```

## 8. 本版变化与验证范围

相对v1.0.2，本版提供Windows桌面一键制谱、最近任务、失败后继续、取消与后台监控；增加独立音源前置检查，并将手型网页和PDF／整套JPG导出接入窗口。配套源码包含字音对齐、持续按弦与新伴奏衔接、边界拍组、变调夹可弹性和打印布局修复。

发布前的本机开发验证包括16组NCM＋TXT整曲生成及实际产物回读、另一个MP3完整入口，以及一首FLAC歌曲经过修复后续跑、网页试听和PDF／JPG导出。部分歌曲在修复过程中重试，不应理解为所有歌曲均在同一最终构建上一次生成成功。发布时另行检查源码语法、EXE编译和窗口自检、压缩包内容与文件摘要；没有完成全新电脑安装验证，也没有完成所有曲谱的逐音人工校对。

如果你需要自己编译EXE，在准备好的项目根目录运行：

```powershell
powershell.exe -NoProfile -ExecutionPolicy Bypass -File .\desktop\build.ps1
```

编译脚本使用Windows的.NET Framework 64位编译器，输出到根目录`弦页制谱.exe`；下载组合包的用户无需执行这一步。
